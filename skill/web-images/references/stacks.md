# Placing webimg output per stack

webimg output is the same everywhere: `<dir>/<slug>-<width>.avif` and `.webp`.
Only the wiring differs. Find the section that matches the repo; reuse the repo's own
helper if it already has one (grep for `<picture`, `img(`, `srcset`).

## PHP sites (dentista.com.py and the php-site-template family)

Files in `assets/img/`. A key → file map in `content/images.php`:

```php
'endodoncia' => ['file' => 'endodoncia-tratamiento-conducto',
                 'alt'  => 'Modelo de una muela cortada que muestra los conductos…',
                 'size' => [1168, 880]],   // real pixel size of the largest variant
```

The key is usually the page slug, so service pages pick it up automatically. The helper
(dentista `inc/app.php`) renders nothing until the files exist, so wiring can land before
images:

```php
function img(string $key, string $class = '', string $sizes = '100vw', bool $eager = false): string
{
    $m = images()['items'][$key] ?? null;
    if (!$m || !is_file(ROOT . '/assets/img/' . $m['file'] . '-640.webp')) return '';
    $b = '/assets/img/' . $m['file'];
    $set = fn($ext) => implode(', ', array_filter(["$b-640.$ext 640w",
        is_file(ROOT . "$b-1280.$ext") ? "$b-1280.$ext 1280w" : null]));
    [$w, $h] = $m['size'] ?? [1280, 960];
    return '<picture class="' . e($class) . '">'
        . (is_file(ROOT . "$b-640.avif") ? '<source type="image/avif" srcset="' . e($set('avif')) . '" sizes="' . e($sizes) . '">' : '')
        . '<source type="image/webp" srcset="' . e($set('webp')) . '" sizes="' . e($sizes) . '">'
        . '<img src="' . e("$b-640.webp") . '" alt="' . e($m['alt']) . '" width="' . (int)$w . '" height="' . (int)$h . '"'
        . ($eager ? ' fetchpriority="high"' : ' loading="lazy" decoding="async"') . '></picture>';
}
```

Check: `php -l` on touched files, `php -S 127.0.0.1:8093 index.php`, curl the pages.

## Static HTML, hand-written

Run webimg with `--public-path /assets/img` (or whatever the site serves) and
`--sizes "<layout width>"`, plus `--eager` for the hero, and paste the printed `<picture>`
snippet into the slot as-is. Without `sizes` the browser assumes 100vw and downloads the
biggest file, so don't skip it.

## Static site generated by a build script (babyshower.com.py: `build-site.mjs` → `dist/`)

Don't edit `dist/` — it's regenerated. Find where the build script renders images
(grep `picture`/`srcset` in the build script and content files, e.g. `content.mjs`) and add
the new slot there in the same shape as existing ones, pointing at the slug. Images go in
the source image folder the build copies from (check the script; often `assets/img/`).
Run the build and check the generated HTML in `dist/` contains the new `<picture>`.
Commit `dist/` only if the repo already tracks it (deploy may serve it).

## Node / Next.js

Put files in `public/assets/img/` (served at `/assets/img/`). Keep webimg's
`public/assets/img/manifest.json` in this stack and read it from a small component, so
alt text and dimensions come from one place:

```tsx
// components/Picture.tsx
import manifest from "@/public/assets/img/manifest.json";

type Props = { slug: string; sizes?: string; priority?: boolean; className?: string };

export function Picture({ slug, sizes = "100vw", priority = false, className }: Props) {
  const entry = manifest.images.find((i: any) => i.filename_base === slug);
  if (!entry) return null;
  const files = entry.files as { file: string; format: string; width: number; height: number }[];
  const set = (fmt: string) =>
    files.filter((f) => f.format === fmt).map((f) => `/assets/img/${f.file} ${f.width}w`).join(", ");
  const webp = files.filter((f) => f.format === "webp");
  const fallback = webp[0];
  const largest = webp[webp.length - 1];
  return (
    <picture className={className}>
      <source type="image/avif" srcSet={set("avif")} sizes={sizes} />
      <source type="image/webp" srcSet={set("webp")} sizes={sizes} />
      <img src={`/assets/img/${fallback.file}`} alt={entry.alt_text}
        width={largest.width} height={largest.height}
        {...(priority ? { fetchPriority: "high" as const } : { loading: "lazy" as const, decoding: "async" as const })} />
    </picture>
  );
}
```

Usage: `<Picture slug="endodoncia-tratamiento-conducto" sizes="(min-width:1024px) 620px, 100vw" priority />`.
Don't route these through `next/image`: they're already optimized, and Hostinger's Node
hosting would re-optimize at runtime for no gain. Check: `npm run build` passes and the page
HTML contains the `<picture>`. Express/EJS or other Node templates: same markup as the
component, rendered from the manifest.

## Native / Expo apps

- In-app images: WebP works on iOS and Android. Use webimg with `--widths` at the sizes the
  screens need (e.g. `750,1125` for full-width on phones), reference the `.webp` files via
  `require()`; AVIF is not safe on older Android.
- App icon and splash are not webimg jobs: generate at 1:1 / the splash ratio, download the
  PNG (1024×1024 for the icon) into the path in `app.json`, and let Expo produce the sizes.

## WordPress migrations

Source is the old site's media (`/wp-json/wp/v2/media?per_page=100&page=N`). Take only
originals (skip `-150x150` style thumbnails), only images that map to a slot in the new
site, and run them through webimg with new slugs and new alt text exactly like a Higgsfield
URL. In cloud sessions the old domain must be on the environment allowlist too. Record them
in the manifest with `source: "wordpress"`.
